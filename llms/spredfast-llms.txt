# Spredfast (now Khoros Marketing)

> Spredfast was an Austin-based social media marketing and management platform — social publishing, engagement, listening and analytics for enterprise brands and agencies. It acquired Mass Relevance in 2013, merged with Lithium Technologies in 2018, and the combined company rebranded as Khoros in 2019. The product line is delivered today as Khoros Marketing. The API surface still carries the Spredfast name in production: the host is api.spredfast.com, OAuth runs on login.spredfast.com, request headers use the `x-sf-` prefix, and the Conversations V1 contract is licensed as "Spredfast API Terms of Use".

## Runtime rules an agent must know

- NO IDEMPOTENCY. No Idempotency-Key, no replay protection, no request-id header on responses. A retried publish POST publishes twice. On a timeout, list before retrying.
- ERRORS ARE NOT RFC 9457. The envelope is `{"status": {"error": {"code", "message"}, "succeeded": false}}`. Branch on `status.succeeded`. Some failures are not JSON at all: an expired token returns an HTML "Developer Inactive" page, and a bad path returns a non-standard `586 Service Not Found`.
- NO PUBLISHED RATE LIMITS. Zero of 149 operations declare a 429 or any rate-limit header, and no figure is documented. There is no budget signal to read.
- NO DEPRECATION SIGNAL. v1 and v2 run side by side with no sunset date, no Deprecation/Sunset header, no migration guide, and zero operations marked deprecated.
- OBJECT TYPES are carried on a `sfEntityType` discriminator field, because the contracts declare no reusable schemas at all.
- PAGINATION is offset-based, and inconsistent: `pageNumber`+`pageSize` on subscription listing, `offset`+`limit` on event data. No cursors, no documented total-count field.
- MULTIPART is a separate path, not a content-type: `POST /conversations/asset?multipart` is a distinct operation from `POST /conversations/asset`.
